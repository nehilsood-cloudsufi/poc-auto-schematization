# What Happens When You Run the Pipeline?

When you run `python src/run_pipeline.py --dataset=bis_bis_central_bank_policy_rate`, the pipeline executes 5 phases in sequence. This document traces what happens at each phase using that BIS dataset as our running example.

---

## Phase 1: Discovery

**Agent:** `DiscoveryAgent` (`src/agents/discovery_agent.py`)
**Purpose:** Scan the `input/` directory and catalog what files exist for each dataset.

**What happens:**
1. Scans `input/bis_bis_central_bank_policy_rate/` for subdirectories
2. Looks for:
   - `test_data/*.csv` — raw input data (required)
   - `input_metadata/*.csv` — optional metadata
   - `schema/*.txt`, `schema/*.mcf` — schema examples (may not exist yet)
3. Creates a `DatasetInfo` object with all discovered paths
4. Writes to state: `current_dataset`, `datasets`, `dataset_count`

**Key file:** `src/state/dataset_info.py` — The `DatasetInfo` class is the "passport" for a dataset. Every downstream agent reads it.

**BIS example:** Discovers `test_data/WS_CBPOL_csv_flat_input.csv` (18 columns, ~32K rows of central bank policy rates for 38 countries).

---

## Phase 2: Sampling

**Agent:** `ProgrammaticSamplingAgent` (`src/agents/sampling_agent_v2.py`)
**Purpose:** Create a small (60-100 row), representative sample and a structural description of the dataset.

**Why not just use the full dataset?** The full CSV can be huge (32K+ rows for BIS). LLMs have token limits. We need a sample that captures the dataset's diversity without exceeding the prompt budget.

**The 6-Step DAG:**
```
1. Profile (pandas)       → DatasetProfile (column types, cardinality, stats)
2. Semantic Analysis (LLM) → SemanticAnalysis (column roles: place, time, dimension, value)
3. Skeleton Mapping (LLM)  → RelationalSkeleton (normalized relational structure)
4. Stratified Sampling     → sampled CSV (60-100 rows covering all dimension values)
5. Grounding (DC API)      → Place DCID resolution
6. Assembly (template)     → skeleton_summary markdown + data_context JSON
```

Steps 1, 4, 5, 6 are deterministic (pandas/API). Steps 2, 3 are LLM calls (Gemini).

**Key outputs:**
- `agentic_sampled.csv` — The sample file (used in the PVMAP prompt)
- `skeleton_summary` — Markdown describing dataset structure (sections for columns, types, dimensions, relationships). This is injected into the PVMAP prompt.
- `data_context.json` — Structural analysis dict (column classifications, stats)

**Key files:**
- `src/pipeline/sampling/profiler.py` — Pandas-based profiling (column types, cardinality, nulls, stats)
- `src/pipeline/sampling/stratified_sampler.py` — Ensures all dimension values are represented
- `src/pipeline/sampling/context_assembler.py` — Builds the skeleton_summary markdown

**BIS example:** For the BIS dataset:
- Profile: 18 columns, identifies FREQ/REF_AREA as categorical, OBS_VALUE as numeric, TIME_PERIOD as date-like
- Semantic: REF_AREA=place, TIME_PERIOD=time, FREQ=dimension, OBS_VALUE=value
- Sample: ~80 rows covering all 38 countries, both Monthly/Daily frequencies
- Skeleton: Markdown describing "This is a central bank policy rate dataset with country and time dimensions"

**Try it yourself:**
```bash
python src/run_pipeline.py --dataset=bis_bis_central_bank_policy_rate --force-resample --skip-schema-selection --skip-evaluation
```

## Phase 2.5: Schema Selection

**Agent:** `SchemaSelectionAgent` (`src/agents/schema_selection_agent.py`)
**Purpose:** Choose which of 7 predefined schema categories best matches this dataset.

**Categories:**
| Category | Example Datasets |
|----------|-----------------|
| Demographics | Population, age, gender, race, household |
| Economy | GDP, business, revenue, trade, **central bank rates** |
| Education | Enrollment, degrees, attainment |
| Employment | Labor force, jobs, wages, unemployment |
| Energy | Power generation, consumption, renewables |
| Health | Disease prevalence, mortality, healthcare |
| School | School metrics, performance, facilities |

**What happens:**
1. Reads the `skeleton_summary` from state (generated by sampling)
2. Sends it to Gemini with category descriptions
3. Gemini responds with the best category (e.g., "Economy")
4. Copies compressed schema vocabulary JSON from `src/resources/schema_examples/Economy/` to the dataset's `schema/` directory
5. Writes to state: `schema_category`, `schema_vocab_content`

**Schema vocab:** Each category has a `schema_vocab.json` (~0.4-5.6KB) containing common properties, types, and enum values for that domain. This vocabulary is injected into the PVMAP prompt so the LLM knows valid DC property names.

**BIS example:** Classified as "Economy". Gets economy-specific vocab including properties like `interestRate`, `FinancialInstrument`, `PercentPerAnnum`.

## Phase 3: PVMAP Generation + Retry Loop

This is the most complex phase. It is a `LoopAgent` containing **10 sequential agents** that can run up to 3 iterations.

**Agent:** `PVMAPRetryLoop` (`src/agents/pvmap_retry_loop.py`)

### The 10 Agents Inside the Loop

```
+-------------------------------------------------------+
|                  PVMAPRetryLoop                        |
|                                                        |
|  1. StatePreparationAgent                              |
|     |                                                  |
|  2. [StatVarDiscoveryAgent]  <- MCP only               |
|     |                                                  |
|  3. PVMAPGeneratorAgent      <- LLM generates PVMAP    |
|     |                                                  |
|  4. MetadataGenerationAgent                            |
|     |                                                  |
|  5. [MCPSpotCheckAgent]      <- MCP only               |
|     |                                                  |
|  6. ValidationAgent          <- runs stat_var_proc.    |
|     |                                                  |
|  7. [MCPErrorResolverAgent]  <- MCP only               |
|     |                                                  |
|  8. QualityEvaluationAgent   <- can ESCALATE (exit)    |
|     |                                                  |
|  9. ConditionalFeedbackAgent <- builds error feedback   |
|     |                                                  |
|  10. MaxRetriesCheckAgent    <- can ESCALATE (exit)    |
|                                                        |
|  Loop back to step 1 with error_feedback               |
+-------------------------------------------------------+
```

Agents in `[brackets]` only run when MCP is enabled (`--enable-mcp`).

### Step-by-Step:

**1. StatePreparationAgent** — Increments `generation_attempt`. Populates the prompt template (`improved_pvmap_prompt.txt`) by replacing placeholders:
- `{{SKELETON_SUMMARY}}` — the skeleton_summary from sampling
- `{{SCHEMA_EXAMPLES}}` — schema vocab content
- `{{SAMPLED_DATA}}` — the sampled CSV data
- `{{ERROR_FEEDBACK}}` — error feedback from previous attempt (empty on attempt 0)
- `{{METADATA_CONFIG}}` — metadata if `--use-metadata` enabled

**3. PVMAPGeneratorAgent** — An `LlmAgent` that receives the populated prompt and generates a PVMAP CSV. Uses Schema.org lookup tools. The raw LLM output is saved to `output/{dataset}/generated_response/attempt_N.md`.

**4. MetadataGenerationAgent** — Auto-generates `output_metadata.csv` with dataset properties.

**6. ValidationAgent** — The critical gate. Three steps:
   a. **PVMAP Repair** (`src/pipeline/validation/pvmap_repair.py`) — Fixes common LLM errors: wrong case, extra whitespace, hallucinated key prefixes. Uses fuzzy matching (0.80-0.85 threshold).
   b. **Pre-validation** — Quick structural checks before the expensive subprocess call. Catches obvious failures (no observationAbout mapping, too many unmatched keys).
   c. **Subprocess validation** — Runs `tools/stat_var_processor.py` on the FULL original dataset (not the sample). Timeout: 5 minutes. If it produces output rows, validation passed.

**8. QualityEvaluationAgent** — Decides whether to exit:
   - Quality acceptable (score >= 70) — **ESCALATE** (exit loop, success)
   - Stagnation detected (< 10% improvement vs previous attempt) — **ESCALATE** (exit loop, best effort)
   - Otherwise — continue to feedback

**9. ConditionalFeedbackAgent** — Builds error feedback from:
   - Validation error logs (sampled to ~300 lines)
   - Key match report (which keys did not match column headers)
   - Compacted skeleton_summary (sections 6, 7, 9 dropped to save tokens)
   - Writes `error_feedback` to state for next iteration

**10. MaxRetriesCheckAgent** — If `generation_attempt >= max_retries` (default 2 in `run_pipeline.py`, so 3 total attempts), **ESCALATE**. Tracks the best attempt and restores it if the current attempt is worse.

### Exit Conditions
1. QualityEvaluationAgent escalates — quality acceptable or stagnant
2. MaxRetriesCheckAgent escalates — used all 3 attempts
3. `max_iterations` reached — fallback safety

**BIS example:** Typically succeeds on attempt 1. The LLM generates the PVMAP, stat_var_processor validates it, quality evaluation passes.

---

## Phase 5: Evaluation

**Agent:** `EvaluationAgent` (`src/agents/evaluation_agent.py`)
**Purpose:** Compare the generated PVMAP against ground truth.

**What happens:**
1. Looks for ground truth in `ground_truth/bis_bis_central_bank_policy_rate/pvmap/`
2. Runs diff-based comparison
3. Calculates metrics:
   - **node_accuracy** — How many StatVar nodes match ground truth
   - **pv_accuracy** — How many individual property-value pairs are correct
4. Saves results to `output/{dataset}/eval_results/`

**BIS example:** Compares generated PVMAP against `bis_bis_central_bank_policy_rate_pvmap.csv`. Typical PV accuracy: ~25%.

**Note:** Evaluation is optional. If no ground truth exists, it gracefully skips. Use `--skip-evaluation` to skip explicitly.

---

## Putting It All Together

When you run the BIS dataset, the timeline looks roughly like:
```
0s   Discovery     -> Found 1 dataset, 18 columns, 32K rows
5s   Sampling      -> 80-row sample, skeleton_summary generated
15s  Schema Select -> "Economy" category, vocab loaded
20s  Gen Attempt 0 -> LLM generates PVMAP (8 rows)
30s  Validation    -> Repair fixes 0-2 keys, subprocess passes
35s  Quality Eval  -> Score 75+, ESCALATE
40s  Evaluation    -> PV accuracy 25%, node accuracy 100%
45s  Done          -> Output in output/bis_bis_central_bank_policy_rate/
```

Total: ~45 seconds for a dataset that would take a domain expert hours to map manually.
