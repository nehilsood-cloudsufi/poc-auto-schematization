# Human Feedback Redesign — Structured Priority & Accumulation

**Date:** 2026-04-10
**Status:** Draft
**Branch:** `feature/nehil/human-feedback-redesign`

## Problem Statement

The current human feedback system is unreliable enough that engineers either give up after 1 round or skip it entirely, manually editing PVMAPs instead. Four failure modes exist:

1. **LLM ignores feedback** — user says "map column X to property Y" and the LLM maps X to something else
2. **Regressions** — fixing one thing breaks something that was working
3. **Partial application** — LLM gets the gist but misses exact values/names
4. **Auto-feedback overwrites human** — auto-generated feedback from `ConditionalFeedbackAgent` replaces human instructions on retry attempts

Root causes:
- Human and auto feedback share a single `error_feedback` string with no priority distinction
- The PVMAP generator prompt labels feedback as "from previous attempts" — no human attribution
- The feedback agent has zero awareness of human instructions and freely contradicts them
- Feedback overwrites on every attempt — no accumulation across rounds
- No programmatic enforcement — everything depends on LLM compliance

## Goals

1. Human feedback corrections must reliably appear in the generated PVMAP
2. Multiple rounds of feedback must accumulate, not overwrite
3. Auto-generated feedback must never contradict human instructions
4. Engineers at all expertise levels (DC experts and newcomers) can give effective feedback
5. Backward compatible — old API calls and prompt templates continue to work

## Non-Goals

- Feedback effectiveness dashboards (nice-to-have, not blocking)
- Cross-dataset feedback learning
- Smart feedback suggestions / auto-populated templates
- Changes to the save-and-revalidate flow (already works)

## Design

### 1. Data Model — The Feedback Ledger

Replace the single `error_feedback` string with a structured, append-only ledger.

#### Types

```python
# src/api/models/feedback.py

class FeedbackType(str, Enum):
    PIN_ROW = "pin_row"          # "Row 5 must be exactly this"
    SET_MAPPING = "set_mapping"  # "Map column X to property Y"
    APPLY_RULE = "apply_rule"    # "All _CODE columns are dimensions"
    FREE_TEXT = "free_text"      # "This column looks wrong"
    AUTO = "auto"                # Auto-generated by feedback agent
```

#### Entry

```python
class FeedbackEntry(BaseModel):
    id: str                      # Unique entry ID (uuid4 hex[:8])
    type: FeedbackType
    round: int                   # Feedback round (1, 2, 3...)
    source: Literal["human", "auto"]
    content: str                 # The instruction text
    target: Optional[str]        # Column name, row index, or None
    retracted: bool = False      # User explicitly retracted this entry
    superseded: bool = False     # Auto-set when a newer entry targets same column
    timestamp: datetime
```

#### Ledger

```python
class FeedbackLedger(BaseModel):
    entries: list[FeedbackEntry] = []

    def active_human_entries(self) -> list[FeedbackEntry]:
        """Non-retracted, non-superseded human entries, ordered by recency."""
        return [
            e for e in self.entries
            if e.source == "human" and not e.retracted and not e.superseded
        ]

    def active_auto_entries(self) -> list[FeedbackEntry]:
        """Non-retracted auto entries. Conflict filtering with human targets
        is handled by FeedbackMerger, not here — the ledger is a data store,
        the merger owns rendering logic."""
        return [
            e for e in self.entries
            if e.source == "auto" and not e.retracted
        ]

    def has_human_entries(self) -> bool:
        return len(self.active_human_entries()) > 0

    def retract(self, entry_id: str) -> bool:
        for e in self.entries:
            if e.id == entry_id:
                e.retracted = True
                return True
        return False

    def render_for_prompt(self) -> tuple[str, str]:
        """Returns (human_section, auto_section) for prompt injection.
        Delegates to FeedbackMerger.render_separate() — this method is
        a convenience wrapper that creates a default merger."""
        from src.api.services.feedback_merger import FeedbackMerger
        return FeedbackMerger().render_separate(self)
```

#### Conflict Resolution Rules

1. Human entries always take precedence over auto entries
2. If an auto entry targets the same column as a human entry, the auto entry is filtered out (by `FeedbackMerger`)
3. Within the same source, recency wins — when a newer entry targets the same column, the older entry is marked `superseded=True`
4. Retracted and superseded entries are preserved in the ledger but excluded from prompt rendering
5. Superseded entries are visible in the UI history panel (shown as "replaced by round N") — user can retract the newer entry to restore the older one

#### State Keys

| Key | Type | Purpose |
|-----|------|---------|
| `feedback_ledger_json` | str (JSON) | **Source of truth** — serialized FeedbackLedger |
| `error_feedback` | str | **Derived** — merged render for backward compat with `{{ERROR_FEEDBACK}}` |
| `human_feedback_prompt` | str | **Derived** — human section only, for `{{HUMAN_FEEDBACK}}` template var |
| `auto_feedback_prompt` | str | **Derived** — auto section only, for `{{AUTO_FEEDBACK}}` template var |
| `auto_feedback_raw` | str | **Temp** — raw ConditionalFeedbackAgent output before ledger parsing |
| `human_feedback_provided` | bool | **Derived** — `ledger.has_human_entries()` |

Note: The config-level `human_feedback` parameter (in `PipelineConfig` and `run_pipeline.py`) remains unchanged — it's the raw input string from the API. The state keys `human_feedback_prompt` and `auto_feedback_prompt` are distinct (suffixed with `_prompt`) to avoid collision.

#### Ledger Persistence Across Runs

The ledger must be accessible from the API layer (for the feedback endpoint to load prior feedback when creating a new run). Since ADK session state is not directly accessible from API routes, the ledger is **dual-persisted**:
1. **In ADK state** as `feedback_ledger_json` — used by agents during pipeline execution
2. **On disk** as `output/{dataset}/feedback_ledger.json` — written by `StatePreparationAgent` after each attempt, read by `feedback.py` when creating re-runs

When `feedback.py` creates a new run with accumulated feedback, it loads the ledger from disk, appends new human entries, and passes the full ledger JSON as part of the run config. `run_pipeline.py` then deserializes it into initial state.

### 2. Backend — Feedback Merger & Priority Enforcement

#### 2A: FeedbackMerger Service

New service at `src/api/services/feedback_merger.py`:

```python
class FeedbackMerger:
    def merge(self, ledger: FeedbackLedger) -> str:
        """Produce the final merged prompt text from the ledger."""
        human = ledger.active_human_entries()
        auto = ledger.active_auto_entries()

        human_targets = {e.target for e in human if e.target}
        auto_filtered = [e for e in auto if e.target not in human_targets]

        sections = []
        if human:
            sections.append(self._render_human_section(human))
        if auto_filtered:
            sections.append(self._render_auto_section(auto_filtered))
        return "\n\n".join(sections)

    def render_separate(self, ledger: FeedbackLedger) -> tuple[str, str]:
        """Return (human_text, auto_text) for two-section prompt templates."""
        human = ledger.active_human_entries()
        auto = ledger.active_auto_entries()
        return (
            self._render_human_section(human) if human else "",
            self._render_auto_section(auto) if auto else "",
        )
```

Rendering formats entries by type:
- `PIN_ROW`: "PINNED ROW {target}: {content} — DO NOT MODIFY THIS ROW"
- `SET_MAPPING`: "REQUIRED MAPPING: Column `{target}` must map to `{content}`"
- `APPLY_RULE`: "RULE: {content}"
- `FREE_TEXT`: "{content}"
- `AUTO`: "{content}"

#### 2B: Feedback-Aware ConditionalFeedbackAgent

Changes to the feedback path in `pvmap_retry_loop.py`:

**Before (current):**
```python
# feedback_agent output_key="error_feedback" → overwrites everything
```

**After:**
```python
# feedback_agent output_key="auto_feedback_raw" → writes to temp key
# StatePreparationAgent reads auto_feedback_raw, creates AUTO entries,
# appends to ledger, renders merged prompt into error_feedback
```

The feedback agent's instruction template gains a new read-only section:

```markdown
## Human Instructions (READ-ONLY — DO NOT CONTRADICT)

{human_instructions_summary}

The above instructions were given by a human expert. Your feedback MUST NOT:
- Suggest changes that contradict any human instruction
- Recommend removing or altering mappings the human explicitly set
- Override pinned rows or explicit column assignments

Focus your analysis on issues the human has NOT addressed.
```

`human_instructions_summary` is populated from `ledger.active_human_entries()` rendered as a compact list.

#### 2C: FeedbackEnforcementAgent (Post-Generation Hard Guarantee)

New agent at `src/agents/feedback_enforcement.py`:

```python
class FeedbackEnforcementAgent(BaseAgent):
    """Programmatically enforce human feedback constraints on generated PVMAP."""

    async def _run_async_impl(self, ctx):
        ledger = deserialize_ledger(ctx.session.state)
        generated_pvmap = ctx.session.state["pvmap_csv"]

        enforced = generated_pvmap
        changes = []

        for entry in ledger.active_human_entries():
            if entry.type == FeedbackType.PIN_ROW:
                enforced, changed = self._enforce_pinned_row(enforced, entry)
                if changed:
                    changes.append(f"Restored pinned row: {entry.target}")
            elif entry.type == FeedbackType.SET_MAPPING:
                enforced, changed = self._enforce_mapping(enforced, entry)
                if changed:
                    changes.append(f"Restored mapping: {entry.target} -> {entry.content}")

        if changes:
            ctx.session.state["pvmap_csv"] = enforced
            ctx.session.state["feedback_enforcement_applied"] = True
            ctx.session.state["feedback_enforcement_changes"] = changes
```

**Pipeline sequence change:**

```
BEFORE: Generator → Repair → Validate → Quality → Feedback → Loop
AFTER:  Generator → Enforce → Repair → Validate → Quality → Feedback → Loop
```

The enforcer runs after generation but before repair/validation. Even if the LLM ignores every instruction, the enforcer programmatically restores pinned rows and explicit mappings.

**Enforcement matching strategy:**
- `PIN_ROW`: Matches by the row's key column value (first column, typically the CSV header name), not by positional index. If the key exists in the generated PVMAP, the entire row is replaced with the pinned content. If the key doesn't exist (LLM restructured completely), the pinned row is appended and a warning is logged.
- `SET_MAPPING`: Matches by column name in the PVMAP's key column. Finds the row where key == target column, then overwrites the specified property/value cells. If the column isn't mapped at all, a new row is created.
- `APPLY_RULE`: Not enforced programmatically — rules are guidance for the LLM, not structural constraints. They appear in the prompt but can't be mechanically verified.

### 3. Prompt Changes

#### PVMAP Generator Prompt (improved_pvmap_prompt_v3.txt)

Replace the single `{{ERROR_FEEDBACK}}` block with two sections:

```markdown
## HUMAN INSTRUCTIONS (MANDATORY — HIGHEST PRIORITY)

{{HUMAN_FEEDBACK}}

These instructions come directly from a human expert who reviewed your previous output.
You MUST follow every instruction above. If any instruction conflicts with other
guidance in this prompt, the human instruction wins. After generating, verify each
human instruction was applied. If you cannot follow an instruction, explain why in
a comment row — but DO NOT silently ignore it.

---

## Auto-Generated Feedback (from validation analysis)

{{AUTO_FEEDBACK}}

If auto-feedback is present: apply fixes ONLY where they do not conflict with
the HUMAN INSTRUCTIONS section above. Human instructions always take precedence.
```

Key differences from today:
- Two separate template variables instead of one
- "MANDATORY" framing mirrors the working pattern from `APPROVED_MAPPING_PLAN`
- Explicit conflict resolution: "human instruction wins"
- Self-verification: "after generating, verify each human instruction was applied"
- Auto-feedback subordinated: "ONLY where they do not conflict"

### 4. Feedback Accumulation — Multi-Round Lifecycle

#### Attempt 0 (first generation with human feedback):

1. `run_pipeline.py`: Parse `human_feedback` string into `FeedbackEntry` objects. Detect type from category ("Column mapping" -> `SET_MAPPING`, etc.). Create ledger. Serialize to `feedback_ledger_json`.
2. `StatePreparationAgent`: Deserialize ledger. Render via `FeedbackMerger`. Set `human_feedback` and `auto_feedback` template vars.
3. Generator runs with both sections in prompt.
4. `FeedbackEnforcementAgent`: Enforce pinned rows/mappings.
5. Repair -> Validate -> Quality check.

#### Attempt 1+ (auto-feedback added):

6. `ConditionalFeedbackAgent`: Writes raw analysis to `auto_feedback_raw` (NOT `error_feedback`).
7. `StatePreparationAgent` (next iteration): Reads `auto_feedback_raw`. Parses into `FeedbackEntry(type=AUTO, source="auto", round=N)`. Appends to ledger. Filters conflicting auto entries. Re-renders merged prompt. Human entries from ALL rounds still present. Previous auto entries replaced by current auto entries.

#### Feedback round 2 (user submits new feedback via UI):

8. `feedback.py` endpoint: Loads existing ledger from previous run's state. Adds new human entries (round=2). Creates new run with full ledger.
9. New run starts at attempt 0 with accumulated ledger: Round 1 human entries (unless retracted) + Round 2 human entries (new) + Auto entries cleared (fresh start).

#### Key rules:

- **Human entries accumulate** across UI feedback rounds
- **Auto entries are per-attempt** — each retry replaces previous auto entries
- **Retraction is explicit** — user marks entry as retracted via API
- **Recency tiebreaker** — when a round 2 human entry targets the same column as a round 1 entry, the round 1 entry is auto-marked `superseded=True` (distinct from retracted — superseded entries are hidden from rendering but visible in the history panel as "replaced by round 2"). User can still manually retract the round 2 entry to restore the round 1 entry.

### 5. UI Enhancements

#### 5A: Enhanced FeedbackForm (Three Tabs)

**Tab 1: "Quick Feedback" (default)**
- Free-text textarea + category dropdown + severity slider (as today)
- Severity now used: 4-5 gets `MUST FOLLOW` framing, 1-3 gets `SHOULD FOLLOW`
- Auto-wrapped as `FREE_TEXT` entry

**Tab 2: "Precise Mapping"**
- Column selector dropdown (populated from PVMAP column headers)
- Property name input with autocomplete (from schema vocab)
- Value/format input (optional)
- "Add mapping" button — adds `SET_MAPPING` entry to visible list
- Can add multiple mappings before submitting

**Tab 3: "Pin Rows from Editor"**
- Shows rows user edited in CsvEditor (using existing `changedCells` diff)
- Each changed row: before/after with "Pin this row" checkbox
- Pinned rows become `PIN_ROW` entries
- Auto-generates structured feedback from diff

#### 5B: Feedback History Panel

Collapsible panel on results page showing accumulated feedback:
- Human entries grouped by round, each with "retract" button
- Auto entries shown as read-only with conflict status
- Retracted items shown as strikethrough

#### 5C: API Changes

```
POST   /runs/{run_id}/feedback           — enhanced: accepts structured entries
GET    /runs/{run_id}/feedback/ledger     — new: returns full ledger
DELETE /runs/{run_id}/feedback/{entry_id} — new: retract an entry
```

Enhanced request model (backward compatible):

```python
class FeedbackRequest(BaseModel):
    # Existing (backward compat)
    text: Optional[str] = None
    category: Optional[str] = None
    severity: int = 3
    # New structured fields
    entries: Optional[list[FeedbackEntryInput]] = None

class FeedbackEntryInput(BaseModel):
    type: FeedbackType
    content: str
    target: Optional[str] = None
```

If `entries` provided, used directly. If only `text/category`, auto-wrapped as `FREE_TEXT`.
