# HOW THE PROCESSOR WORKS

The processor converts each data cell into a StatVarObservation by collecting PVs from:
1. **Column Header** -> collects those PVs
2. **Cell Value** -> collects those PVs
3. **Row Header** -> collects those PVs
4. **Merge** -> all PVs form the complete observation

**Key Insight**: Column header properties apply to ALL cells in that column.

**Carry-forward**: If a column header's PVs lack `value`/`measurementResult`, those PVs carry forward to subsequent columns as row-level context (defining the StatVar). This is how dimension columns work — they add constraints that apply to value columns that follow.

# CORE RULES

## Rule 1: observationAbout (The Anchor)

**EVERY observation MUST have observationAbout** — the geographic/organizational unit being measured.

**Detection Decision Tree:**
1. **FIPS/GeoID column?** → `FIPS,#Format,observationAbout=geoId/{Data:0>5}`
2. **ISO/Country Code?** → `REF_AREA,observationAbout,country/{Data}`
3. **Composite values?** (e.g., `State/UT:Delhi`) → Use `#Regex` to extract
4. **Place names?** → Dynamic `observationAbout,wikidataId/{Data}` (NEVER hardcode only visible values)
5. **Constant place?** → Add `observationAbout,country/USA` to value columns

**SAMPLE WARNING:** The data is a SMALL SAMPLE. Use DYNAMIC patterns (using `{Data}` or `#Regex`), not hardcoded visible values.

## Rule 2: Pre-Formatted Data Detection

If data has `variableMeasured`, `observationAbout`, `observationDate`, and `value` columns — it's already in DC format. Use passthrough:
```csv
key,property,value
observationAbout,observationAbout,{Data}
observationDate,observationDate,{Data}
variableMeasured,variableMeasured,{Data}
value,value,{Number}
```
**DO NOT** construct new `variableMeasured` entries or add `populationType`/`measuredProperty`/`statType`.

## Rule 3: Prefer Decomposed Properties Over variableMeasured DCIDs

**DO NOT** use `variableMeasured,dcid:Count_Person_65OrMoreYears` shortcuts.
**DO** decompose into properties: `populationType,Person,age,[65 - Years],value,{Number}`

The decomposed form:
- Enables the processor to construct StatVar DCIDs correctly
- Supports margin-of-error (M_) and percentage (EP_/MP_) variants
- Works with measurementDenominator for ratio calculations
- Matches ground truth patterns used across Data Commons

The only exception: pre-formatted data that already has a `variableMeasured` column with valid DCIDs (see Rule 2 above).

## Rule 4: Entity vs Attribute + StatVar Design

**Entity columns** (place, organization) → DYNAMIC `{Data}` mapping, NEVER enumerate.
**Attribute columns** (gender, age, race) → EXPLICIT enumeration with `COLUMN:VALUE` syntax.

A StatVar is: `populationType` + `measuredProperty` + `statType` + constraint properties.
**Place and Time are NEVER part of the StatVar** — they belong to the Observation only.

If two rows share Place + Time but differ in value, their StatVars MUST differ — you missed a dimension.

## Rule 5: Exact Vocabulary + No Placeholders

- Use EXACT Data Commons property names (`populationType` not `populationGroup`, `measuredProperty` not `measurement`)
- Age ranges use bracket notation: `[65 - Years]`, `[18 64 Years]`, `[0 17 Years]`
- FORBIDDEN: placeholder keys like `p2`, `v2`, `dcid:v2`, `FIXME`
- FORBIDDEN: `dcid:` prefix on property values. Write `populationType,Person` NOT `populationType,dcid:Person`. Write `observationAbout,geoId/{Data}` NOT `observationAbout,dcid:geoId/{Data}`. The processor adds dcid: internally.
- NEVER map `variableMeasured` — it's auto-constructed by the processor (except Rule 2 passthrough)

# DATA ARCHETYPE RECOGNITION

Classify your data FIRST, then apply the matching PVMAP strategy:

| Archetype | Signature | PVMAP Strategy | Key Pattern |
|-----------|-----------|---------------|-------------|
| **Wide/Flat** | 1 row = 1 observation, value in dedicated column | Map headers directly; `value,{Number}` | Pattern A |
| **Wide/Multi-value** | Multiple value columns per row (dates or metrics as headers) | Each value column = separate PVMAP row with ALL properties | Pattern B |
| **Tidy/Long** | Indicator column + value column | Map indicator unique values; `variable_col:X,prop,val` | Pattern D |
| **Dimension/Row** | Row values carry dimension info, columns carry measurements | COLUMN:VALUE syntax for dimensions; carry-forward for headers | Pattern C |
| **Census/Coded** | E_/M_/EP_/MP_ prefixes for same concept | Separate row per prefix with appropriate statType | Pattern F |
| **Passthrough** | Already has observationAbout/variableMeasured/value columns | Direct pass-through mapping | Rule 2 |

### Census/Coded Pattern (E_/M_/EP_/MP_ prefixes)

**APPLIES ONLY TO** US Census Bureau data with these exact column prefixes:

| Prefix | Meaning | StatType | Extra Properties |
|--------|---------|----------|------------------|
| `E_` | Estimate | `measuredValue` | — |
| `M_` | Margin of Error | `marginOfError` | — |
| `EP_` | Estimate % | `measuredValue` | `unit,Percent`, `measurementDenominator,-[constraint]` |
| `MP_` | MOE % | `marginOfError` | `unit,Percent`, `measurementDenominator,-[constraint],-statType` |

**DO NOT collapse** these variants into a single row. Each prefix requires its own PVMAP row.

### First Principles Fallback (for unseen data types)

If your data doesn't match any archetype above:
1. Identify the INVARIANT: which column(s) identify the entity being measured? → `observationAbout`
2. Identify the TIME: which column has dates/years? → `observationDate`
3. Everything else: either a dimension (constrains StatVar, low cardinality) or a value (measurement, numeric)
4. Map dimensions with COLUMN:VALUE syntax, values with `value,{Number}` + full StatVar properties

# COMPACT SYNTAX REFERENCE

## Format
`key,property1,value1,property2,value2,...`
- Keys must **exactly match** column headers (case-sensitive) or cell values
- `COLUMN:VALUE` syntax for values in specific columns
- Quote keys containing commas: `"ICD-10:#Heart",causeOfDeath,X`
- CSV must be parseable by Python csv.reader

## Placeholders
- `{Data}` — raw string value from cell
- `{Number}` — numeric value from cell
- `{Key}` — the key string that was looked up

## #Format — Zero-pad and Build Composite IDs
```csv
FIPS,#Format,"observationAbout=geoId/{Number:05d}"
statefips,#Format,StateFips={Number:0>2}
countyfips,#Format,"observationAbout=geoId/{StateFips}{Number:0>3}"
```

## #Regex — Extract with Named Groups
```csv
REF_AREA,#Regex,"^(?P<Code>[A-Z]+):.*",observationAbout,country/{Code}
```
Must use named groups `(?P<Name>...)`.

## #ignore — Drop Rows
```csv
Series ID,#ignore,skip
```

## #Aggregate — Combine Duplicate Observations
When multiple input rows produce the same StatVar+place+date, use `#Aggregate` to combine:
```csv
Janeiro,observationDate,{Year}-01,observationPeriod,P1M,value,{Number},#Aggregate,sum
```
Supported values: `sum`, `mean`, `max`, `min`. Use `sum` by default for counts.

## Named Variable Capture — Construct Compound Values
Capture a column value as a named variable for use in other rows:
```csv
year,Year,{Number},variableMeasured,Count_FireEvent
Janeiro,observationDate,{Year}-01,observationPeriod,P1M,value,{Number}
```
The first row captures the `year` column value as `{Year}`. The second row constructs `observationDate` as `{Year}-01` (e.g., "2020-01"). Variable names match the column header exactly (case-sensitive).

## #Multiply — Unit Conversion
When source data is in scaled units (thousands, millions), use `#Multiply` to convert:
```csv
"Employment (thousands)",value,{Number},populationType,Person,measuredProperty,count,#Multiply,1000
```
This multiplies the cell value by 1000 before creating the observation.

## Place Prefix Quick-Reference
| Prefix | Use For |
|--------|---------|
| `country/{Data}` | ISO country codes (USA, IND, FRA) |
| `geoId/{Data}` | Standard IDs — US FIPS, ISO numeric |
| `wikidataId/{Data}` | Local regions globally (not just India) |
| `nuts/{Data}` | EU NUTS codes |

Choose by **ID type**, not geography. `geoId/` works for US AND international ISO codes.
Extract units from headers: `(USD)` → `unit,USDollar`, `(%)` → `unit,Percent`, `(thousands)` → `scalingFactor,1000`.

**When to enumerate places explicitly:**
If the place column contains names (not standard codes) that cannot resolve via `{Data}`:
- Brazilian states → `wikidataId/Q...` (e.g., Acre → `wikidataId/Q40780`)
- Indian states → `wikidataId/Q...`
- City names → `wikidataId/Q...`

Use dynamic `{Data}` only when the column contains standardized codes (ISO alpha-2/3, FIPS, NUTS).
For non-standard names, enumerate each unique place value with its Wikidata DCID.

## Required Properties
**Observation**: `value`, `observationDate`, `observationAbout`
**StatVar**: `populationType`, `measuredProperty`, `statType` + constraints

# WORKED EXAMPLES

## Example 1: Wide/Flat with Semantic Headers (OECD/FAO)

**Input:**
```csv
Country,Year,GDP per capita (USD),Unemployment Rate (%)
FRA,2020,40000,8.5
DEU,2020,45000,3.2
```

**PVMAP:**
```csv
key,property,value
Country,observationAbout,country/{Data}
Year,observationDate,{Data}
"GDP per capita (USD)",value,{Number},populationType,EconomicActivity,measuredProperty,amount,measurementMethod,PerCapita,unit,USDollar
"Unemployment Rate (%)",value,{Number},populationType,Person,measuredProperty,unemploymentRate,unit,Percent
```

---

## Example 2: Dimension/Row with #Regex (India NDAP)

**Input (sample shows 3 states, dataset has 28+):**
```csv
State/UT,OBS_Year,Gender,Life expectancy in years
State/UT:Jammu And Kashmir,2020,Male,68.5
State/UT:Delhi,2020,Female,72.3
```

**PVMAP:**
```csv
key,property,value
"State/UT",#Regex,"^State/UT:(?P<StateName>.*)",observationAbout,wikidataId/{StateName}
OBS_Year,observationDate,{Data}
Gender:Male,gender,Male
Gender:Female,gender,Female
"Life expectancy in years",value,{Number},populationType,Person,measuredProperty,lifeExpectancy,statType,measuredValue,unit,Year
```

---

## Example 3: Census/Coded with E_/M_/EP_/MP_ + #Format (US Census SVI)

**Input:**
```csv
FIPS,year,E_AGE65,M_AGE65,EP_AGE65,MP_AGE65
01001,2020,5000,150,12.5,0.3
```

**PVMAP:**
```csv
key,property,value
FIPS,#Format,observationAbout=geoId/{Data:0>5}
year,observationDate,{Number}
E_AGE65,populationType,Person,age,[65 - Years],value,{Number}
M_AGE65,statType,marginOfError,populationType,Person,age,[65 - Years],value,{Number}
EP_AGE65,populationType,Person,age,[65 - Years],measurementDenominator,-age,unit,Percent,scalingFactor,100,value,{Number}
MP_AGE65,statType,marginOfError,populationType,Person,age,[65 - Years],measurementDenominator,"-age,-statType",unit,Percent,scalingFactor,100,value,{Number}
```
