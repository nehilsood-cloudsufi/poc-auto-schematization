# HOW THE PROCESSOR WORKS

The processor converts each data cell into a StatVarObservation by collecting PVs from:
1. **Column Header** -> collects those PVs
2. **Cell Value** -> collects those PVs
3. **Row Header** -> collects those PVs
4. **Merge** -> all PVs form the complete observation

**Key Insight**: Column header properties apply to ALL cells in that column.

# CRITICAL RULE #1: observationAbout (The Anchor)

**EVERY observation MUST have observationAbout** - This is the geographic/organizational unit being measured.

**Detection Decision Tree:**
1. **Is there a FIPS/GeoID column?** (Look for: `FIPS`, `GEOID`, `State Code`, `County Code`)
   - Action: Map with `#Format` for zero-padding: `FIPS,#Format,observationAbout=geoId/{Data:0>5}`

2. **Is there an ISO/Country Code column?** (Look for: `REF_AREA`, `ISO`, `Country Code`)
   - Action: Map to `observationAbout,{Data}` or `observationAbout,country/{Data}`

3. **Is there a Wikidata/International ID column?** (Look for India states, non-US regions)
   - Action: Map using `wikidataId/` prefix: `State,observationAbout,wikidataId/{Data}`

4. **Is there a COMPOSITE/EMBEDDED place column?** (Values like `State/UT:Delhi`, `Region: North`)
   - Action: Use `#Regex` to extract: `"State/UT",#Regex,"^State/UT:(?P<Place>.*)",observationAbout,wikidataId/{Place}`
   - CRITICAL: When a column contains delimiters (`:`, `-`, `|`), extract the place name portion

5. **Is there a Name column?** (Look for: `City`, `State`, `Country`, place names)
   - Action: Create COMPREHENSIVE explicit mappings for ALL values, not just sample values
   - CRITICAL: The sample data shows only a few values - you MUST map ALL possible values

6. **Is the Place constant?** (All data is about one place, e.g., USA)
   - Action: Add `observationAbout,country/USA` to all value columns

**SAMPLE WARNING:** The data provided is only a SMALL SAMPLE. If a column contains place names, assume there are MANY MORE values than shown. Generate a DYNAMIC mapping pattern (using `{Data}` or `#Regex`) rather than hardcoding only the visible values.

**If you cannot satisfy one of these 6 conditions, STOP and report 'Missing Place Dimension'.**

# CRITICAL RULE #2: Detect Pre-Formatted Data Commons Data

**BEFORE generating PVMAP, check if data is ALREADY in Data Commons format:**

### Detection Criteria:
1. **Has `variableMeasured` column** with DCID values like:
   - `dcid:Count_Person_Female`
   - `dcid:CumulativeCount_FoodBasket_Delivered`

2. **Has `observationAbout` column** with place/entity DCIDs:
   - `country/USA`, `geoId/06`, `wikidataId/Q391149`

3. **Has `observationDate` column** with standard formats

4. **Has `value` column** with numeric measurements

### If Pre-Formatted -> Use Passthrough Mapping:

```csv
key,property,value
observationAbout,observationAbout,{Data}
observationDate,observationDate,{Data}
variableMeasured,variableMeasured,{Data}
value,value,{Number}
```

**DO NOT:**
- Try to construct new `variableMeasured` entries
- Parse or deconstruct existing DCIDs
- Add `populationType`, `measuredProperty`, `statType` to columns that already have `variableMeasured`

# CRITICAL RULE #4: Entity vs Attribute (Dynamic vs Enumerated)

**Columns serve ONE of TWO roles:**

1. **ENTITY COLUMNS (observationAbout)** - The SUBJECT being measured (Place, Organization)
   - Use **DYNAMIC mapping** with `{Data}` placeholder
   - Examples: State, Country, District, Region, FIPS
   - **NEVER enumerate individual values** - use `observationAbout,wikidataId/{Data}`

2. **ATTRIBUTE COLUMNS (constraintProperties)** - Characteristics defining the StatVar
   - Use **EXPLICIT enumeration** for small, fixed sets
   - Examples: Gender (Male/Female), Age groups
   - Enumerate: `gender:Male,gender,Male` and `gender:Female,gender,Female`

**Detection Heuristics:**
| Indicator | Column Type | Mapping Strategy |
|-----------|-------------|------------------|
| High cardinality (many unique values) | Entity | Dynamic `{Data}` |
| Geographic names (States, Districts) | Entity | Dynamic `{Data}` |
| Fixed small set (Male/Female, Yes/No) | Attribute | Explicit enumeration |
| Prefixed values (State/UT:X, Region:X) | Entity | `#Regex` extraction |

**THE CRITICAL MISTAKE:** The sample data shows only 3 states, but the full dataset has 28.
**NEVER hardcode only visible values** - generate a pattern that works for ALL values.

# CRITICAL RULE #5: StatVar Design & Dimension Coverage

**NOTE:** This was previously Rule #4. Rule #4 is now Entity vs Attribute.

## The StatVar Formula
A StatVar is defined by: `populationType` + `measuredProperty` + `statType` + `[constraint properties]`

**Place and Time are NEVER part of the StatVar** - they belong to the Observation only.

## Total Constraint Coverage
If a column describes a subset of the population (e.g., "Male", "Rural", "Ages 18-25"), it MUST be represented as a property in the StatVar mapping:

```csv
# Dimension columns constrain the StatVar
gender:Male,gender,Male
gender:Female,gender,Female
age:0-17,age,[0 17 Years]
age:65+,age,[65 - Years]
race:White,race,WhiteAlone
```

## Uniqueness Check
If two rows have the same Place and Time but different values, there MUST be a difference in their StatVar definitions. If the StatVars look identical, you have failed to capture a dimension.

# CRITICAL RULE #6: Exact DC Vocabulary

**Use EXACT Data Commons property names and DCIDs:**

### Common Pitfalls:
| Wrong | Correct |
|-------|---------|
| `NoHighSchoolDiploma` | `LessThanHighSchoolDiploma` |
| `SpeaksEnglishLessThanWell` | `SpeakEnglishLessThanVeryWell` |
| `Years65Onwards` | `[65 - Years]` |
| `Below150PercentPovertyLevel` | `[- 1.5 RatioToPovertyLine]` |
| `benefitProgram` | `beneficiaryProgram` |
| `populationGroup` | `populationType` |
| `measurement` | `measuredProperty` |

### Age Range Syntax:
Use bracket notation: `[Start End Unit]`
- `[65 - Years]` (65 and older)
- `[18 64 Years]` (18 to 64)
- `[0 17 Years]` (0 to 17)

# PV MAP FORMAT

`key,property1,value1,property2,value2,...`

- Keys must **exactly match** column headers or cell values (case-sensitive)
- Use `COLUMN:VALUE` syntax for values in specific columns (e.g., `place:Alabama`)
- Quote keys containing commas/special chars: `"ICD-10:#Heart (I00-I51)",causeOfDeath,X`

## CSV Escaping Rules

1. **Backslashes must be escaped**: Use `\\` for literal backslash
2. **Quotes inside quoted fields**: Use double quotes `""`
3. **Commas in keys**: Must double-quote the entire key
4. **Validation**: Ensure each line is parseable by Python csv.reader

# PATTERN F: STATISTICAL TYPE VARIANTS (US Census/ACS SPECIFIC)

**APPLIES ONLY TO:** US Census Bureau data with specific column prefixes.
**DO NOT APPLY TO:** International data (India NDAP/NFHS, OECD, FAO, Korea, Brazil) unless they explicitly use these exact prefixes.

When data has E_, M_, EP_, MP_ prefixes for the same concept:

| Prefix | Meaning | StatType | Additional Properties |
|--------|---------|----------|----------------------|
| `E_` | Estimate (count) | `measuredValue` | - |
| `M_` | Margin of Error | `marginOfError` | - |
| `EP_` | Estimate Percent | `measuredValue` | `unit,Percent`, `measurementDenominator,-[constraint]` |
| `MP_` | Margin of Error % | `marginOfError` | `unit,Percent`, `measurementDenominator,-[constraint],-statType` |

**Example:**
```csv
# Base estimate
E_AGE65,populationType,Person,age,[65 - Years],value,{Number}
# Margin of error
M_AGE65,statType,marginOfError,populationType,Person,age,[65 - Years],value,{Number}
# Percentage estimate
EP_AGE65,populationType,Person,age,[65 - Years],measurementDenominator,-age,unit,Percent,scalingFactor,100,value,{Number}
# Percentage margin of error
MP_AGE65,statType,marginOfError,populationType,Person,age,[65 - Years],measurementDenominator,"-age,-statType",unit,Percent,scalingFactor,100,value,{Number}
```

**DO NOT collapse these variants into a single row.** Each prefix requires its own PVMAP row.

# DATA PATTERNS

## Pattern A: Flat Data (one observation per row)
```csv
REF_AREA,#Regex,"^(?P<Code>[A-Z]+):.*",observationAbout,country/{Code}
```

## Pattern B: Wide Data (multiple value columns)

**CRITICAL**: Each column MUST include ALL properties - no inheritance between columns.

```csv
Jan 2015,observationDate,2015-01,value,{Number},populationType,Person,measuredProperty,count,statType,measuredValue,observationAbout,country/USA
Feb 2015,observationDate,2015-02,value,{Number},populationType,Person,measuredProperty,count,statType,measuredValue,observationAbout,country/USA
```

## Pattern C: Row+Column Combinations
```csv

Male,gender,Male,value,{Number},populationType,Person,measuredProperty,count,statType,measuredValue
Female,gender,Female,value,{Number},populationType,Person,measuredProperty,count,statType,measuredValue

```



# SPECIAL SYNTAX

## Placeholders
- `{Data}` - Raw string value from cell
- `{Number}` - Numeric value from cell
- `{Key}` - The key string that was looked up

## Intermediate Variables
Capitalize to capture for later use (not included in StatVar):
```csv
year_col,Year,{Number}
month_col,#Regex,"M(?P<Month>[0-9]+)"
value_col,observationDate,{Year}-{Month},value,{Number}
```

## #Format - Zero-pad Values and Build Composite IDs
```csv
# Zero-padding for FIPS codes
FIPS,#Format,"observationAbout=geoId/{Number:05d}"
state_fips,#Format,"observationAbout=geoId/{Number:02d}"

# Composite FIPS (state + county)
statefips,#Format,StateFips={Number:0>2}
countyfips,#Format,"observationAbout=geoId/{StateFips}{Number:0>3}"
```

**PREFER #Format over hardcoded mappings** for ID columns (FIPS, ISO codes).

## #Regex - Extract with Named Groups
```csv
REF_AREA,#Regex,"^(?P<Code>[A-Z]+):.*",observationAbout,country/{Code}
```
**Must use named groups** `(?P<Name>...)` - unnamed groups don't work.

## #Eval - Python Expressions
```csv
Status,#Eval,"active='Yes' if '{Data}' == 'Y' else 'No'"
```

## #ignore - Drop Rows
```csv
Series ID,#ignore,skip
```

# PLACE FORMATS (BY ID AUTHORITY, NOT REGION)

**IMPORTANT:** Choose prefix by **ID type**, not geography. geoId works for ANY standard ID.

| Format | Example | Use Case | ID Authority |
|--------|---------|----------|--------------|
| `country/{Data}` | `country/USA`, `country/IND` | ISO-3 country codes | ISO 3166-1 |
| `geoId/{Data}` | `geoId/06`, `geoId/IN` | Standard IDs (FIPS, ISO) | General |
| `geoId/{Number:05d}` | `geoId/01001` | US county FIPS (zero-padded) | US Census |
| `wikidataId/Q{Data}` | `wikidataId/Q1353` | Local admin regions, cities | Wikidata |
| `nuts/{Data}` | `nuts/DEF0` | EU NUTS classification | Eurostat |
| `ibge/{Data}` | `ibge/3304557` | Brazilian municipal codes | IBGE |
| `iso/{Data}` | `iso/IN-KA` | ISO 3166-2 subdivisions | ISO |
| `Earth` | `Earth` | Global data | - |

**Prefix Selection by ID Type (NOT by Country):**
- **Standard codes** (2-3 letter ISO, numeric FIPS) -> Use `geoId/`
- **Wikidata Q-IDs** (Q + digits, e.g., `Q1353`) -> Use `wikidataId/`
- **NUTS codes** (2-letter + alphanumeric, e.g., `FR10`) -> Use `nuts/`
- **ISO 3166-2** (2-letter + hyphen, e.g., `IN-KA`) -> Use `iso/`
- **Brazilian municipal** (7-digit IBGE) -> Use `ibge/`

**KEY INSIGHT:** `wikidataId/` is NOT "for India" - it's for ANY local region globally that lacks standard codes. `geoId/` works for US AND international ISO codes.

**Dynamic construction does NOT work**: `observationAbout,{Country}/{City}` fails.

**Use explicit mappings for place names:**
```csv
Country or Area:Åland Islands,observationAbout,country/AX
srcStateName:Punjab,observationAbout,wikidataId/Q22424
"State/UT:Delhi",observationAbout,wikidataId/Q1353
"State/UT:Karnataka",observationAbout,wikidataId/Q1185
```

# COMMON MISTAKES TO AVOID

1. **Missing observationAbout** - causes 0 output rows
2. **Placeholder columns** (p2, v2, dcid:v2) - pollutes output
3. **Inexact DCIDs** - use exact DC vocabulary
4. **Collapsing E_/M_/EP_/MP_ variants** - each needs separate row
5. **Hardcoded mappings for IDs** - use #Format for FIPS/ISO codes
6. **Dynamic place construction** - use explicit mappings for names
7. **Missing StatVar properties on value columns**
8. **Ignoring dimension columns** - they constrain the StatVar

1. Use `#Regex` to extract place names from composite values
2. Map Gender as ATTRIBUTE (explicit enumeration) - small fixed set
3. Map State/UT as ENTITY (dynamic pattern) - high cardinality
