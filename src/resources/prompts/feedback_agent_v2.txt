## Processor-Focused Analysis Framework

Classify the failure, then follow the matching path:

### COVERAGE-BASED TRIAGE (check Processing Metrics FIRST)
- 0 output rows -> PATH A (key matching problem — fix keys)
- 1-80% coverage -> PATH B (partial mapping — find which keys fail)
- 80%+ coverage -> PATH C (semantic/quality issues — fix property names)

### PATH A: 0 output rows (total failure)
- **Key mismatches**: PVMAP keys don't match column headers (case, whitespace, hallucinated segments)
- **Missing required properties**: no observationAbout, observationDate, or value mapping
- **Missing dcs: prefix**: Schema node values (populationType, measuredProperty, enum values) MUST use dcs: prefix. Example: populationType,dcs:Person NOT populationType,Person. Exception: placeholders ({Data}, {Number}) and place IDs (geoId/, country/) do NOT get prefixed.
- **#ignore contamination**: If PVMAP contains #ignore entries, remove them. Unmapped columns are automatically skipped. #ignore corrupts StatVar DCIDs.
- **#Eval errors**: f-strings (f"...") NOT supported; nested double quotes break CSV parsing — use single quotes

### PATH B: Some output rows but not all (partial failure)
- Which columns are producing rows vs which are failing silently?
- **Column coverage gaps**: unmapped dimension columns cause StatVar collapse (different dimension values treated as same observation)
- **Place resolution failures**: observationAbout values can't resolve to DC places — use FIPS codes or DCIDs instead of place names

### PATH C: Full output, low quality (semantic issues)
- All rows mapped but property-value pairs may be wrong
- Check quality score breakdown for weakest component
- Common causes: wrong DC property names, missing dcs: prefix on enum values, wrong populationType/measuredProperty
- Use Schema Domain Context below to find correct property names
- If PVMAP is verbose (100+ COLUMN:VALUE rows), suggest passthrough {Data} pattern for high-cardinality dimensions

### Root Cause Checklist (check in this order)
1. Key mismatch (case/whitespace/hallucinated segments)
2. Missing required properties (observationAbout, observationDate, value)
3. Missing dcs: prefix on schema nodes (must use dcs: for types/enums/codes)
4. Column mapping errors (wrong column for place/time/value)
5. #Eval syntax errors (f-strings, nested quotes)

- **Incompatible properties**: May still be valid DC extensions. Only flag if truly wrong.

## Interpreting Processing Metrics

The Processing Metrics section contains enriched diagnostics. Pay attention to these sections:

### Error Priority
Errors are ordered by IMPACT, not count. Fix them in order:
1. PVMAP Key Mismatch -- blocks ALL output. Fix first.
2. Place Resolution -- unlocks many rows once fixed.
3. Missing StatVar/Observation properties -- completeness.
4. Duplicate Observations -- need qualifier properties.

### Failing Values
When "Failing values:" appears under an error, these are the SPECIFIC values causing failures.
Use them to write targeted fixes:
- If failing places are single-digit numbers (6, 1, 9): add zero-padding (geoId/[val:0>2])
- If failing places are names (Alabama, New York): switch to FIPS codes
- If failing keys are wrong case: match exact column header from Key Match Report

### Systematic Patterns
When "Systematic Patterns Detected" appears, it means many errors share a root cause.
A single fix (e.g., changing a format string) can resolve dozens of errors at once.
Always check this section FIRST before writing individual fixes.

### Iteration Guidance
Follow the iteration-specific strategy at the bottom of the metrics.
Early attempts: fix structure. Later attempts: preserve working rows.

| Coverage | Diagnosis | Action |
|----------|-----------|--------|
| 0% (0 rows) | Keys don't match any data | Check exact column headers from Key Match Report |
| < 50% | Major mapping gaps | Identify unmapped columns |
| 50-90% | Partial -- some types failing | Fix specific failing patterns |
| 100% | All rows mapped | Focus on property/format/quality |

Fragmentation ratio (unique_statvars / total_observations): < 0.05 compact (good for dimension-rich), 0.05-0.3 healthy, 0.3-0.8 moderate (check categoricals), > 0.8 nearly 1:1 (dimension treated as defining property).
